## Core canon (read directly from the landed core repo)

- `core/hooks/lib/role-directive.sh` — `core_role_directive <you_decide> <use_when> <produces> <hand_off>`, reads `CLAUDE_ROLE`, honors `<ROLE>_CYCLE_OFF` (role name upper-cased via `tr`), emits the same directive shape this repo's `directive.sh` currently hand-writes, then a fixed `RECORD:` line.
- `core/hooks/hooks.json` registers `board-gate.sh`, `approval-gate.sh`, `gh-guard.sh`, `trailer-gate.sh`, `record-fields-gate.sh`, `handbook-trigger-gate.sh` on `PreToolUse` (matcher `.*`) plus `directive.sh` on `SessionStart` — globally, once, for every role via `CLAUDE_ROLE`.
- `core/hooks/tests/stub-check.sh` — the drift-recurrence detector issue-2 item 5 asks this record to confirm passing. Two checks: (a) absence-based for `trailer-gate.sh`/`record-fields-gate.sh`/`handbook-trigger-gate.sh`/`parse-check.sh` anywhere under the target dir (maxdepth 3) — any vendored copy is a FAIL; (b) structural for `directive.sh` — must source `role-directive.sh`, must call `core_role_directive`, and **every other non-blank/non-comment/non-shebang/non-assignment line in the file must itself match one of those two patterns** — i.e. the `core_role_directive` call must be a single physical line. Verified empirically against a scratch copy: a multi-line (backslash-continued or literal-newline) call FAILS the check; a single physical-line call, including one using `$'...\n...'` ANSI-C quoting to embed real newlines inside one argument, PASSES.
- `warrant/agents/warrant-hunter.md` — the canon hunt agent (core issue #63), stance-rotation/reproduction/one-file-per-work-unit-record protocol. This rulebook's own copy is an adapted skeleton whose header literally says "adapted from implementation-rulebook's `agents/warrant-hunter.md`" and defers stance enumeration — never a shipped, role-specific artifact.
- `core/.claude-plugin/plugin.json` documents core as the canon owner of these seven hooks plus the two shared library/test files, "parameterized on CLAUDE_ROLE rather than vendored per role."

## Gaps found, relevant to the proposal

1. **directive.sh's role-unique content exceeds the stub's 4 slots.** `core_role_directive` only emits `you_decide`/`use_when`/`produces`/`hand_off` + a fixed `RECORD:` line. This rulebook's current directive also carries `WRITE_SCOPE: []` and a `BOUNDARY CASE:` paragraph that `core_role_directive` has no parameter for. Confirmed by direct testing (above) that these can be folded into the `produces`/`hand_off` string arguments via `$'...\n\n...'` without breaking `stub-check.sh`'s one-call-per-line rule — losing them silently was the alternative, and the issue text says role-unique content is preserved, not dropped.
2. **`RECORD_FIELDS_TERMINAL_STATES` value for this role is unresolved.** capacity-planning is declared report-only (`WRITE_SCOPE: []`); nothing in this repo currently records what `loop_state` values this role's own record uses, terminal or not — this repo's phase-2 record (`docs/issue-2/reports/implementation.md`) does not exist yet, so there is no existing usage to read. Default (`landed`) is very likely sufficient for a report-only role; treated as an open decision in the proposal rather than assumed.
3. **`capacity-planning/agents/warrant-hunter.md` has no registration to remove** — it's a Markdown agent definition, not wired through `hooks.json`; removing the file is the entire action for item 1.
4. **No `warrant` plugin dependency currently declared** in `capacity-planning/.claude-plugin/plugin.json` — removing this rulebook's own copy relies on the `warrant` plugin being installed/available at the marketplace level (outside this repo's control), consistent with how `core` itself is referenced (no explicit dependency manifest found in this plugin.json either — install ordering is a marketplace/session concern, not something this rulebook's own files declare).
